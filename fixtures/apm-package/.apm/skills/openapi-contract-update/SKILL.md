# OpenAPI contract update

Use when updating public API documentation or OpenAPI specs.

1. Align documented paths, methods, and status codes with the implementation.
2. Keep request/response schemas and examples consistent with real behavior.
3. Document error responses with stable machine-readable codes.
4. Use safe example data: no real secrets, personal data, or card values.
5. Note any breaking change explicitly with migration guidance.
