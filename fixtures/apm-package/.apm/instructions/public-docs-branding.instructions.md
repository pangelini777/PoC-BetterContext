# Public documentation branding and accuracy

Apply to externally visible documentation.

- Use the product name `Acme Checkout` consistently; do not invent product tiers, availability claims, certifications, or performance guarantees.
- Examples must use fake hosts, IDs, emails, and credentials.
- Commands and API examples should be executable or explicitly marked as pseudocode.
- When documenting an API behavior, match the implemented status codes, field names, and error semantics.
- Avoid marketing superlatives and unsupported claims such as `instant`, `always`, `fully compliant`, or `unbreakable`.
- Call out breaking changes and migration requirements plainly.
